Getting started

Documentation

Everything you need to inspect Android APKs with APK Analyzer Pro. Learn how the analyzer works, what each view shows, and how to extract, export and interpret the results.

APK Analyzer Pro is a 100% client-side Android package inspector. Every operation — binary XML decoding, DEX parsing, technology detection, security scanning — runs in your browser. Your APK never leaves your device.

✓
No installation, no upload, no account

Open the analyzer, drop an APK, and start inspecting immediately. Compatible with Chrome, Firefox, Safari, Edge and Opera on both desktop and mobile.

Real parsing

Binary AXML decoder, DEX header parser and string table reader — no mocks, no placeholders.

Security checks

Nine automated checks for common Android misconfigurations, categorised by severity.

Folder tree

Browse the internal structure of the APK. Extract any file, folder or the entire package.

Quick start

Analyze your first APK in under thirty seconds.

1

Open the analyzer

Click Launch Analyzer from the topbar, or navigate directly to apk-analyzer.html.

2

Drop your APK

Click the drop zone to open a file picker, or drag an APK file straight onto the page. The analyzer accepts .apk, .xapk and .apks files.

3

Wait for analysis

A progress overlay shows each stage: reading, hashing, opening the ZIP archive, decoding the manifest, parsing DEX files, detecting technologies, running the security scanner.

4

Explore the results

Use the sidebar to navigate between Overview, Manifest, DEX Explorer, Security, Technologies and Files.

!
Large APKs may take a moment

Files over 200 MB spend most of their time in the ZIP decompression stage. APKs under 500 MB work comfortably on modern hardware.

Overview tab

The Overview tab gives you a snapshot of the package — its identity, size distribution, detected stack and top permissions. It's the first place to look when you open a new APK.

Stat cards

Four summary cards at the top of the Overview tab:

CardWhat it shows
APK sizeThe total size of the file, plus the compression ratio achieved by the ZIP container.
DEX filesNumber of classes*.dex files and the total class count across all of them.
Total filesTotal number of entries inside the ZIP archive, plus the count of native libraries.
FindingsTotal number of security findings, with a count of critical + high severity items.

Package identity

The identity section reads directly from the decoded AndroidManifest.xml. Fields shown:

  • Package — the unique application ID (e.g. com.example.app)
  • Version name — user-facing version string
  • Version code — integer version counter used by the Play Store
  • Min SDK — the lowest Android API level the app supports
  • Target SDK — the API level the app was built and tested against
  • Main activity — the launcher activity that opens when the app starts
  • Application — the custom Application subclass, if any
  • Debuggable — whether the app allows debugger attachment
  • Allow backup — whether app data can be extracted via adb backup
  • SHA-256 — hash of the entire APK file

Size breakdown

A horizontal bar chart showing how the APK's bytes are distributed across six categories:

CategoryContents
DEXAll classes*.dex files — compiled Dalvik bytecode.
Native librariesEverything under lib/, split by ABI (arm64-v8a, armeabi-v7a, x86, x86_64).
Resourcesres/, resources.arsc and AndroidManifest.xml.
AssetsBundled assets under assets/ — fonts, ML models, web content.
SignaturesEverything under META-INF/.
OtherAny remaining entries.
i
Use the size chart to spot bloat

An APK with 40 MB of native libraries usually means multiple ABI builds. An APK with 30 MB of assets typically bundles ML models or offline content.

Manifest viewer

Android packages ship their manifest in a compact binary XML format called AXML. The analyzer decodes it into readable, syntax-highlighted XML you can copy and inspect.

What's decoded

  • String pool — UTF-8 and UTF-16 string tables
  • Element tree — nested tags with attributes
  • Typed values — references, integers, booleans, colours
  • Attributes — every android: attribute is resolved to its actual value
Decoded manifest (excerpt)
<manifest xmlns:android="http://schemas.android.com/apk/res/android" package="com.example.app" android:versionCode="42" android:versionName="2.4.1"> <uses-sdk android:minSdkVersion="24" android:targetSdkVersion="34" /> <uses-permission android:name="android.permission.INTERNET" /> <application android:debuggable="false" android:allowBackup="false"> <activity android:name=".MainActivity" android:exported="true"> <intent-filter> <action android:name="android.intent.action.MAIN" /> <category android:name="android.intent.category.LAUNCHER" /> </intent-filter> </activity> </application> </manifest>

Permissions list

Below the decoded manifest, every uses-permission is listed as a tag. Dangerous permissions — those requiring runtime user consent — are highlighted in red using the official Android platform list.

Components

Activities, services, broadcast receivers and content providers are listed with their export state:

BadgeMeaning

DEX Explorer

DEX files contain an Android app's compiled Dalvik bytecode. The DEX Explorer reads each file's header and reports its structure.

Metrics per DEX file

MetricDescription
ClassesNumber of class definitions — the DEX header's class_defs_size field.
MethodsTotal method references across the whole file.
FieldsTotal field references.
StringsNumber of unique strings in the string pool.
i
The 64K method limit

Android's DEX format originally capped method references at 65,536 per file. Apps that exceed this split their code across classes.dex, classes2.dex, classes3.dex and so on. The analyzer reports the total across all files.

Aggregate counts

The bottom of the DEX view sums classes, methods, fields and strings across every DEX file — a useful signal for app complexity and code size.

Security scanner

The Security tab runs nine automated checks against the decoded manifest and the package contents. Findings are categorised by severity: critical, high, medium and info.

See the Security checks reference below for a full description of every check and why it matters.

Technologies

The Technologies tab identifies frameworks, libraries and languages by scanning file paths and DEX strings against a library of signatures.

Detection sources

  • File paths — e.g. lib/*/libflutter.so signals Flutter, assets/flutter_assets/ confirms it
  • DEX strings — e.g. retrofit2/ indicates Retrofit, com.google.firebase indicates Firebase

Native libraries & architecture

The same tab lists every .so file and the ABIs present in the APK. A pure Java/Kotlin app with no native code shows an empty native libraries list.

File Explorer

The Files tab renders the internal structure of the APK as an expandable folder tree. Every folder can be expanded to reveal its contents, including nested subfolders.

Tree interactions

  • Click a folder to expand or collapse it — the chevron rotates 90°
  • Search auto-expands every folder that contains a match and dims the rest
  • Expand all opens the entire tree
  • Collapse all returns to root level

Reading the tree

✓
Folder sizes are recursive

Clicking a folder shows the sum of every file beneath it. A folder like res/ with hundreds of drawables shows its total weight immediately — no need to expand it.

Extraction

The analyzer extracts files directly from the APK's ZIP container using JSZip. Every extraction is performed in memory and downloaded to your machine.

Extract a single file

Click Extract on any file row. The file downloads immediately with its original name and contents.

Extract a folder

Click Extract on any folder row. A new ZIP is generated containing every file under that folder — subfolders preserved — and downloaded as foldername.zip.

Example: extracting res/
res.zip ├── drawable-hdpi/ │ └── icon.png ├── drawable-mdpi/ │ └── icon.png ├── layout/ │ ├── activity_main.xml │ └── fragment_details.xml ├── values/ │ ├── strings.xml │ └── colors.xml └── xml/ └── network_security_config.xml

Extract the entire APK

Click Extract all in the toolbar to pack the entire decompressed APK into a single ZIP. The output is named <apkname>-contents.zip.

!
Large extractions take a moment

Packing hundreds of files into a ZIP in the browser takes time. A toast notification confirms progress and completion.

!
The scanner is not a guarantee

A clean result means the automated checks found nothing — it does not prove the APK is safe. Always combine this analysis with source review, dynamic testing and your own judgement.

Privacy & security

Everything the analyzer does happens inside your browser tab. Your APK, its contents and the analysis results never leave your device.

No server uploadsYour APK is read into memory with the File API. Nothing is transmitted over the network.
No analytics on your dataThe analyzer does not send any information about your APK — not even a filename hash.
Local-only processingAXML decoding, DEX parsing and ZIP extraction all run client-side using JavaScript.
No account, no cookiesThere is nothing to sign up for and nothing to track you across visits.

How to verify

  1. Open your browser's developer tools (F12 or Cmd+Option+I)
  2. Switch to the Network tab
  3. Load and analyze an APK
  4. Observe that no requests carry the APK data — only static assets (HTML, CSS, JS, fonts) and the JSZip library from a CDN
✓
Works fully offline after first load

Once the page and CDN assets are cached, you can disconnect from the internet and still analyze APKs. The analysis engine has no external dependencies at runtime.

Troubleshooting

"Not a valid APK / ZIP file"

The file you dropped is not a ZIP archive. Common causes:

  • The file is a split APK bundle (.apks) — extract the base APK first
  • The file is an Android App Bundle (.aab), which is not a ZIP of the same structure
  • The file is corrupted or incomplete

"AndroidManifest.xml not found"

The ZIP opened but does not contain an Android manifest. Either the file is not an Android APK, or the manifest is at a different path (common in some split-APK scenarios).

"Manifest decode failed"

The manifest was found but the binary AXML parser rejected it. This is rare and usually indicates a non-standard APK or a truncated manifest file.

Analysis is very slow

  • Large APKs (> 200 MB) spend most time in ZIP decompression — expected
  • Check that no other tabs are consuming memory — the analyzer holds the entire decompressed APK plus string tables in RAM
  • Try a desktop browser for very large packages; mobile browsers have stricter memory limits

Extract button does nothing

Some browsers block downloads triggered without a clear user gesture. Make sure you are clicking the button directly, not triggering it programmatically.

Missing technologies

The detector matches paths and DEX strings. If a library is heavily obfuscated or embedded in a way that hides its package names, detection may miss it.

Frequently asked questions

Does my APK leave my device?

No. Every operation runs locally in your browser. See the Privacy section for verification steps.

Is there a size limit?

There is no hard limit, but APKs under 500 MB are recommended. Larger files depend on your device's memory and CPU.

Does it decompile an APK to Java source?

No. The analyzer extracts and inspects package contents — manifest, DEX headers, resources, permissions. Full source decompilation requires dedicated tools like JADX or APKTool.

Can it detect malware?

Not directly. The scanner reports common misconfigurations and dangerous permissions, but it is not an antivirus and does not have a malware signature database.

Is it free?

Yes. APK Analyzer Pro is presented as free and open source, with no subscriptions or premium tiers.

Which browsers are supported?

Modern Chrome, Firefox, Safari, Edge and Opera on both desktop and mobile. Internet Explorer is not supported.

Can I use this commercially?

The tool is presented as open source. Check the project's licence for exact terms.

How do I report a bug or request a feature?

Open an issue on the GitHub repository. Include the browser version, the APK's general characteristics (size, target SDK) and the behaviour you observed — but never attach proprietary APKs to a public issue.
